# MaterialManagement 重构前后对照草图（2026-04-21）

## 1. 目标

用低保真结构草图说明：
- 当前 `MaterialManagement.vue` 是什么形态
- 第一阶段拆分后会变成什么形态
- 第二阶段工作台化后会变成什么形态

---

## 2. 当前形态（Before）

```text
┌───────────────────────────────────────────────┐
│ ConfigCenterShell                              │
│   Header actions                               │
├───────────────────────────────────────────────┤
│ 顶部摘要卡（写在页面里）                        │
├───────────────────────────────────────────────┤
│ 搜索区（写在页面里）                            │
├───────────────────────────────────────────────┤
│ 主数据引用检查（写在页面里）                    │
│ 关系异常分组（写在页面里）                      │
│ 可自动修复 / 需人工处理（写在页面里）           │
├───────────────────────────────────────────────┤
│ 最近审计记录（写在页面里）                      │
├───────────────────────────────────────────────┤
│ 物料表格（写在页面里）                          │
├───────────────────────────────────────────────┤
│ 编辑弹窗（写在页面里）                          │
└───────────────────────────────────────────────┘
```

### 问题
- 页面本体职责过多
- 诊断区块太重
- 审计 / 摘要 / 诊断 / 表格都混在同一个文件里
- 后续再做详情工作台时扩展会越来越乱

---

## 3. 第一阶段目标形态（After Phase 1）

```text
┌───────────────────────────────────────────────┐
│ ConfigCenterShell                              │
│   Header actions                               │
├───────────────────────────────────────────────┤
│ <MaterialSummaryCards />                       │
├───────────────────────────────────────────────┤
│ 搜索区（暂留页面）                              │
├───────────────────────────────────────────────┤
│ <MaterialDiagnosticsPanel />                   │
├───────────────────────────────────────────────┤
│ <MaterialAuditPanel />                         │
├───────────────────────────────────────────────┤
│ 物料表格（暂留页面）                            │
├───────────────────────────────────────────────┤
│ 编辑弹窗（暂留页面）                            │
└───────────────────────────────────────────────┘
```

### 优势
- 页面立即瘦身
- 风险低
- 不需要先大改 composable
- 后续继续拆 List / Detail 更顺

---

## 4. 第二阶段目标形态（After Phase 2）

```text
┌───────────────────────────────────────────────┐
│ ConfigCenterShell                              │
│   Header actions                               │
├───────────────────────────────────────────────┤
│ <MaterialSummaryCards />                       │
├───────────────────────────────────────────────┤
│ 搜索 / 筛选区                                  │
├───────────────────────┬───────────────────────┤
│ <MaterialListPanel /> │ <MaterialDetailPanel />│
│                       │                       │
│                       │ Tabs:                 │
│                       │ - 基础信息             │
│                       │ - 关系                 │
│                       │ - 诊断                 │
│                       │ - 审计                 │
├───────────────────────┴───────────────────────┤
│ <MaterialEditDialog />                         │
└───────────────────────────────────────────────┘
```

### 优势
- 变成真正的“主数据工作台”
- 列表和详情分离
- 用户可以连续查看 / 修复问题
- Material 页更接近主数据平台心智

---

## 5. 页面职责变化

### 当前页面职责
- 布局
- 摘要
- 诊断
- 审计
- 表格
- 弹窗
- 状态编排

### 第一阶段后页面职责
- 布局
- 搜索区
- 表格
- 弹窗
- 状态编排

### 第二阶段后页面职责
- 只保留：
  - 页面编排
  - 选中态
  - 事件转发
  - 状态协调

---

## 6. 拆分建议顺序

### 第一批
1. `MaterialAuditPanel.vue`
2. `MaterialSummaryCards.vue`
3. `MaterialDiagnosticsPanel.vue`

### 第二批
4. `MaterialListPanel.vue`
5. `MaterialDetailPanel.vue`
6. `MaterialRelationshipSection.vue`

### 第三批
7. `MaterialEditDialog.vue`

---

## 7. 成功标准

### 第一阶段成功标准
- `MaterialManagement.vue` 体积明显下降
- 功能行为不变
- 诊断和审计区块职责清晰

### 第二阶段成功标准
- 页面具备“列表 + 详情工作台”结构
- 关系与诊断修复路径更顺
- 页面本体只保留编排职责

---

## 8. 一句话结论

`MaterialManagement.vue` 的最稳重构路径，是先拆出 Summary / Diagnostics / Audit 三块纯展示组件，再升级为双栏工作台结构。
