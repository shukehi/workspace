## ✨ 重构改进

### 1. 消除代码重复 - DRY原则

**提取公共函数**：
```javascript
// ✅ 提取 preparePOData 公共函数
const preparePOData = (po, autoPrint = false) => {
    const orderData = {
        customerName: po.supplier,
        code: po.sourceOrders,
        list: po.items
    };

    localStorage.setItem('_order_preview_data', JSON.stringify(orderData));
    localStorage.setItem('_order_preview_po_number', po.poNumber);
    localStorage.setItem('_order_preview_category', po.category);
    
    if (autoPrint) {
        localStorage.setItem('_order_preview_auto_print', 'true');
    } else {
        localStorage.removeItem('_order_preview_auto_print');
    }
};

// ✅ 简化的 viewPO - 只需 3 行
const viewPO = (po) => {
    preparePOData(po, false);
    modal.value = {
        show: true,
        url: `/order-preview.html?t=${Date.now()}`
    };
};

// ✅ 简化的 printPO - 只需 3 行
const printPO = (po) => {
    preparePOData(po, true);
    modal.value = {
        show: true,
        url: `/order-preview.html?t=${Date.now()}`
    };
};
```

**代码行数对比**：
- 重构前：`viewPO (15行) + printPO (15行) = 30行`
- 重构后：`preparePOData (14行) + viewPO (3行) + printPO (3行) = 20行`
- **减少：33%** ✅

---

### 2. 简化状态管理 - 单一职责

**合并相关状态**：
```javascript
// ❌ 之前：两个独立的 ref
const showPreviewModal = ref(false);
const previewUrl = ref('');

// ✅ 现在：单一的响应式对象
const modal = ref({
    show: false,
    url: ''
});
```

**优势**：
- ✅ 语义更清晰：`modal.show` 和 `modal.url` 明显属于同一个概念
- ✅ 更新更简洁：`modal.value = { show: true, url: '...' }`
- ✅ 易于扩展：未来可以添加 `modal.title`、`modal.size` 等属性
- ✅ 原子更新：Vue 3 会将整个对象的更新视为一次操作

---

### 3. 优化组件注册 - 按需引入

**移除不必要的全局注册**：

```javascript
// ❌ WorkbenchApp.js - 重构前
import { PreviewModal } from './PreviewModal.js';

components: {
    PreviewModal,  // 不需要在这里注册
    OrdersTab,
    // ...
}
```

```javascript
// ✅ WorkbenchApp.js - 重构后
// 移除了 PreviewModal 的导入

components: {
    OrdersTab,  // PreviewModal 只在 OrdersTab 中本地注册
    // ...
}
```

**原因**：
- PreviewModal 只在 OrdersTab 中使用
- 本地注册可以减少全局命名空间污染
- 提升代码的可读性和可维护性

### 4. 清理冗余注释

**移除不必要的注释**：

```javascript
// ✅ 现在

    alert('导出功能待实现/整合');

    const file = event.target.files[0];
```

**原则**：
- ✅ 好的代码应该是自解释的
- ✅ 注释应该解释"为什么"，而不是"做什么"
- ✅ alert 本身已经说明了功能状态，不需要额外注释

## 💡 进一步优化建议

虽然当前的重构已经显著改善了代码质量，但仍有一些可以考虑的优化方向：

### 1. 使用 Composable 提取逻辑

```javascript
// 创建 usePreviewModal.js
export function usePreviewModal() {
    const modal = ref({ show: false, url: '' });

    const preparePOData = (po, autoPrint = false) => { /* ... */ };
    
    const openPreview = (po, autoPrint = false) => {
        preparePOData(po, autoPrint);
        modal.value = {
            show: true,
            url: `/order-preview.html?t=${Date.now()}`
        };
    };

    const closePreview = () => {
        modal.value = { show: false, url: '' };
    };

    return {
        modal,
        openPreview,
        closePreview
    };
}

// 在 OrdersTab 中使用
const { modal, openPreview, closePreview } = usePreviewModal();

const viewPO = (po) => openPreview(po, false);
const printPO = (po) => openPreview(po, true);
```

**优势**：
- 逻辑完全独立，可在其他组件复用
- 更符合 Vue 3 Composition API 的最佳实践

### 2. 使用 Enum 管理状态

```javascript
const ModalMode = {
    VIEW: 'view',
    PRINT: 'print'
};

const modal = ref({
    show: false,
    url: '',
    mode: null
});

const openModal = (po, mode) => {
    preparePOData(po, mode === ModalMode.PRINT);
    modal.value = {
        show: true,
        url: `/order-preview.html?t=${Date.now()}`,
        mode
    };
};

const viewPO = (po) => openModal(po, ModalMode.VIEW);
const printPO = (po) => openModal(po, ModalMode.PRINT);
```
