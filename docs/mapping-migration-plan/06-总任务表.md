### 仍待推进

1. `E0-3` 仍是部分完成：锁芯 / 锁叉正式 published API 还未实现，但契约草案已形成。
2. `E0-7` 仍需继续扩真实单：当前新增的 4 个 case 都是 derived edge cases，还缺多张真实历史订单。
3. `E0-1 / E0-5` 已有建议结论：`secondarySpecialRules` 推荐兼容现网自带 variants 形态，但 validator 还未正式按该规则收口。
4. `A-7` 仍是部分完成：当前只有 validator 骨架，最终 published 契约相关校验还未进入。
5. `B` 仍未开始：迁移脚本、导出脚本、真实 JSON 初始化、`/published` 契约验证全部未进入。

### 进入 A+B 前的额外 Gate

1. 至少补齐 1 批以上真实历史订单样本，覆盖锁叉复杂组合与历史异常单。
2. 把 `docs/mapping-migration-plan/07-published-contract-draft.md` 收敛成正式实现依据，之后才能开始 `/published`。
3. 按“兼容现网自带 variants”规则正式收口 `secondarySpecialRules` validator。
4. `GET /api/config/mappings/:type/published` 需要等第 2 条和第 3 条落到代码后再进入实现。
5. migration 只有在 baseline 足够、published 契约冻结并且 validator 收口后才可开始。

### 当前结论

1. 可以继续推进 A 阶段剩余低风险项。
2. 还不能进入 B 阶段。
3. 进入 B 前，仍需解决“真实样本覆盖不足”这一剩余主阻塞，并把契约草案 / `secondarySpecialRules` 建议正式落到后续实现规则中。

## 关键依赖关系

1. `E0-1 / E0-10` 是全项目前置条件。
2. `A` 完成后才能做 `B`。
3. `B` 至少完成 published API 后，`C` 才能真正切到 SQLite。
4. `C` 稳定后再做 `D`，否则管理台和运行时同时变动，风险过高。
5. `E` 必须最后做。
