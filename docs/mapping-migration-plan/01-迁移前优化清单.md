   - `secondaryDimensions` 只有 `7`
   - `secondarySpecialRules` 只有 1 条

   - `9` 不存在于 `secondaryDimensions`

2. 也就是说，现网已经存在“非引用式、自洽 rule”形态，而不是所有 rule 都依赖 `secondaryDimensions`。

### 决策建议

1. 推荐采用方案 B：
   - 兼容现网
   - 允许 `secondarySpecialRules` 在 `thickness` 不命中 `secondaryDimensions` 时，依靠自身 `variants` 自洽
2. 不推荐方案 A：

   - 若 `thickness` 命中 `secondaryDimensions`，允许 rule 使用 `variants` 做 override

## 五、处理历史追溯

### 1. 决定历史单据是否按当前 published 重算
1. 这是迁移前必须拍板的业务规则。
2. 如果要求可追溯，订单或打印快照应记录 mapping revision。

### 本轮拍板

1. 已生成的采购单、打印快照、历史单据默认不按“当前 published”自动重算。
2. 历史重打优先使用当时固化的解析结果；后续若 revision 引用可用，则按记录下来的 revision 重放。
3. 若历史单据既没有固化快照，也没有 revision 引用，不允许静默回退到“当前 published”重算；只能走显式“重新生成 / 重新分析”操作，并标记为非历史重现结果。
4. 管理台发布新映射后，默认只影响新生成结果，不反向污染已落库的历史输出。

### 2. 推荐记录 revision 引用
1. 至少记录：
   - packaging revision
   - cylinder revision
   - lock_fork revision

### 本轮拍板补充

1. 后续进入实现时，采购单 / 打印快照至少要持有三类 mapping revision 引用之一或全部。
2. 若打印内容已经是完整解析后的快照，则 revision 引用用于追溯，不作为重算前提。

### 3. 打印快照尽量固化已解析结果
1. 避免后来映射变更导致历史重打口径漂移。

### 本轮拍板补充

1. 打印快照的优先级高于运行时重新解析。
2. 历史重打默认使用快照，不再重新触发包装 / 锁芯 / 锁叉匹配。

## 六、明确数据库与工作流语义

### 1. 明确 revision 规则
1. 每个 profile 最多一个 draft。
2. publish 后旧 published 自动 archived。
3. `active_revision` 只指向当前 published。
4. draft update 必须带 revision 乐观锁。

### 本轮拍板

1. revision 按 profile 单调递增，不复用、不回写旧 revision 编号。
2. 每个 profile 在任意时刻最多一个 draft。
3. draft 保存必须带 revision / version 乐观锁；落后版本提交直接拒绝。
4. publish 只能从当前 draft 发起，并且必须先通过 validator + baseline smoke test。
5. publish 成功后：
   - 新 revision 进入 `published`
   - 旧 `published` 自动转 `archived`
   - `active_revision` 只指向新 `published`
6. rollback 不直接把旧 revision 改回 `published`；应复制目标历史 revision 内容生成新 draft，再发布成一个新的 published revision。

### 本轮拍板补充：published 契约草案

1. 锁芯 / 锁叉 `published` API 统一返回 envelope：
   - `success`
   - `mapping.profileCode`
   - `mapping.revision`
   - `mapping.schemaVersion`
   - `mapping.updatedAt`
   - `mapping.payload`
2. v1 的 `mapping.payload` 保持与当前 canonical DTO 一致，不在 B 阶段引入字段裁剪。
3. `configLoader` 后续接入 `published` API 时，只读取 `mapping.payload`，版本与刷新信息读取 envelope 元字段。

### 2. 补唯一约束和状态约束
1. `unique(profile_id, revision)`
2. `profile_code` unique
3. `state` 枚举约束

### 本轮拍板补充

1. `state` 仅允许 `draft / published / archived`。
2. 旧 published 一旦 archived，不允许原地回切状态，只能通过 rollback 生成新 revision。

### 3. 复用 formula 工作流，但不直接照搬
1. 可复用 revision / publish / rollback / audit 模式。
2. mapping 领域不需要 formula 那种实体级建模复杂度。
