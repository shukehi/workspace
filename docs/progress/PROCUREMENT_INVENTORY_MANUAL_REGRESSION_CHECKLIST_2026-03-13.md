# 采购与库存链路人工回归清单（2026-03-13）

## 1. 目标

本清单用于人工验证当前采购与库存主链路是否已经达到阶段可验收状态。

重点覆盖：

1. 到货登记
2. 部分入库
3. 全部入库完成
4. 入库记录查看与跳转
5. 部分撤销
6. 导出与分页筛选一致性

## 2. 回归前准备

准备至少 1 张可操作的采购单，要求：

1. 订单状态可推进到 `arrived`
2. 至少包含 1 条可入库明细
3. 最好包含 2 条明细，便于验证“部分入库”与“部分撤销”

建议同时确认：

1. 对应物料已在库存表中存在
2. 当前库存页能正常打开
3. 当前浏览器允许打开新页面和下载 CSV

## 3. 核心流程

### 3.1 到货登记

1. 在采购页找到一张 `processing` 订单
2. 点击“登记到货”
3. 期望结果：
   - 状态变为 `arrived`
   - 交货日期未被清空
   - 页面无报错 toast

### 3.2 部分入库

1. 对该 `arrived` 订单点击“执行入库”
2. 打开明细入库弹窗
3. 只填写部分明细或部分数量
4. 点击“确认入库”
5. 期望结果：
   - toast 显示“部分入库成功”
   - 订单状态仍为 `arrived`
   - 再次打开弹窗时，已入库数量与剩余待入库数量正确

### 3.3 全部入库完成

1. 再次打开同一订单的入库弹窗
2. 补齐剩余待入库数量
3. 点击“确认入库”
4. 期望结果：
   - toast 显示“入库完成”
   - 订单状态变为 `completed`
   - 列表显示入库日期
   - “执行入库”按钮不再显示

## 4. 库存页联动

### 4.1 查看入库记录

1. 在采购页点击“查看入库记录”
2. 跳转到库存页
3. 期望结果：
   - 自动按订单号定位
   - 当前查询结果能看到目标订单的入库记录
   - URL 中包含当前筛选条件

### 4.2 轨迹抽屉

1. 在库存页点击“轨迹”
2. 期望结果：
   - 可看到原始入库流水
   - 可看到净入库数量
   - 若已有撤销流水，可看到撤销子流水
   - 可从抽屉中跳回采购页定位订单

## 5. 部分撤销

1. 在库存页找到正向入库记录
2. 点击“撤销”
3. 只填写部分撤销数量
4. 选择撤销原因并提交
5. 期望结果：
   - 撤销成功
   - 入库记录新增一条反向流水
   - `reversed_quantity / reversible_quantity` 更新正确
   - 若订单原本为 `completed`，采购页刷新后状态回退为 `arrived`

## 6. 导出与分页

### 6.1 查询条件一致性

1. 在库存页设置：
   - 订单号
   - 方向
   - 撤销原因
   - 关键字
2. 确认列表结果已刷新
3. 点击导出
4. 期望结果：
   - 导出结果按当前已生效查询条件生成
   - 不是只导出当前页
   - CSV 包含方向、撤销原因、剩余可撤销

### 6.2 分页状态

1. 切换页码和 `pageSize`
2. 刷新页面
3. 使用浏览器前进/后退
4. 期望结果：
   - `page / pageSize / orderNo / keyword / direction / reverseReason` 能恢复
   - 页面无空页或明显口径错误

## 7. 异常场景

### 7.1 无剩余待入库明细

1. 找一张所有明细都已入库完成的订单
2. 期望结果：
   - 列表中不显示“执行入库”按钮
   - 不会打开“当前订单没有可继续入库的明细”的空弹窗

### 7.2 历史兼容订单

1. 找一张历史单据，确认曾存在 `ordered_quantity = 0` 的兼容风险
2. 期望结果：
   - 仍能正确显示“执行入库”入口
   - 弹窗中的采购数量和剩余待入库数量计算正常

## 8. 通过标准

满足以下条件即可视为本轮人工回归通过：

1. 主流程可完整走通
2. 状态流转与页面提示一致
3. 导出、分页、筛选口径一致
4. 撤销后库存、订单状态、审计记录三者一致
5. 无明显空弹窗、错误入口、错误状态残留
