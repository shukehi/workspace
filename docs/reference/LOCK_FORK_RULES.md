## 概述

系统会自动从订单中提取锁叉信息（字段：`sc`），并根据以下规则生成采购明细：

- **锁叉分类**：单头锁叉、双头锁叉
- **子类**：T型、P66、直杆/弯杆、中控、螺纹等
- **一个订单会生成上头和下头两条采购明细**

## 基础尺寸规则

### 5cm / 7cm 常规基础尺寸

| 类型 | 上头基础 | 下头基础 |
|------|---------|---------|
| 标准（无吊脚） | 570 + 301 = 871 | 570 + 301 = 871 |
| 带吊脚 | 570 + 301 = 871 | 570 + 313 = 883 |

### 5cm / 7cm 高门基础尺寸（门高 >= 2200）

| 类型 | 上头基础 | 下头基础 |
|------|---------|---------|
| 标准（无平下档/吊脚） | 570 + 376 = 946 | 570 + 376 = 946 |
| 平下档 / 吊脚 | 570 + 376 = 946 | 570 + 388 = 958 |

### 9cm 高门基础尺寸（门高 >= 2210）

| 类型 | 上头基础 | 下头基础 |
|------|---------|---------|
| 标准 | 524 + 422 = 946 | 524 + 272 = 796 |
| 平下档 / 吊脚 | 524 + 422 = 946 | 524 + 272 = 796 |

> **注意**：5cm 与 7cm 当前共用同一套基础尺寸；平下档和吊脚共用 `withHangingFeet` 分支。

## 高度调整计算

### 常规门高基准：2050mm

当门高不等于 2050mm 时，需要进行高度调整：

**公式**：
```
高度调整值 = (实际门高 - 2050) / 2
```

**示例 1：2150mm 门高**
```
高度调整 = (2150 - 2050) / 2 = 50mm

上头 = 570*301 + 50 = 921
下头 = 570*301 + 50 = 921
```

**示例 2：1950mm 门高**
```
高度调整 = (1950 - 2050) / 2 = -50mm

上头 = 570*301 - 50 = 821
下头 = 570*301 - 50 = 821
```

### 5cm / 7cm 高门基准：2200mm

当门厚为 `5` 或 `7` 且门高大于等于 `2200` 时，切换到高门规则。

**公式**：
```
高度调整值 = (实际门高 - 2200) / 2
```

**示例：2400mm 门高**
```
高度调整 = (2400 - 2200) / 2 = 100mm

上头 = 570*376 + 100 = 1046
下头 = 570*376 + 100 = 1046
```

### 9cm 高门基准：2210mm

当门厚为 `9` 且门高大于等于 `2210` 时，切换到 9cm 高门规则。

**公式**：
```
高度调整值 = (实际门高 - 2210) / 2
```

**示例：2410mm 门高**
```
高度调整 = (2410 - 2210) / 2 = 100mm

上头 = 524*422 + 100 = 1046
下头 = 524*272 + 100 = 896
```

## 吊脚检测与调整

### 检测规则

系统从 `xsbz`（销售备注）字段检测吊脚关键字：
- **关键字**：`吊脚`、`diaojiao`
- **提取数值**：如 "吊脚5mm" → 5

### 标准吊脚：35mm

**调整公式**：
```
吊脚调整值 = 35 - 实际吊脚值
```

**示例：吊脚 5mm**
```
吊脚调整 = 35 - 5 = 30mm

上头 = 570*301 = 871（无调整）
下头 = 570*313 + 30 = 913
```

> **重要**：吊脚调整**仅应用于下头**，上头保持标准尺寸

### 完整示例：2400mm 门高 + 吊脚 5mm（7cm 高门）

```
高度调整 = (2400 - 2200) / 2 = 100mm
吊脚调整 = 35 - 5 = 30mm

上头 = 570*376 + 100 = 1046
下头 = 570*388 + 100 + 30 = 1088
```

## 边型分类

### T型边检测

**触发条件**：`mb`（门边）字段包含 `"T型"`

**效果**：在锁叉名称中添加 "T型" 后缀

**示例**：
```
原始名称：单头锁叉
检测到 mb = "T型现代边"
最终名称：单头锁叉 T型
```

**例外规则**：
当以下条件同时满足时，锁叉名称**不添加** `"T型"`：
- `mb` 包含 `"T型铝材边"`
- `mshd = "10"`，识别为 10cm 门厚
- `spec` 中包含 `"内开"`，例如 `970*2040/10/内开外包`

如果遇到 10cm 门厚，门边为 “T型”，而且是内开门，则使用正常的锁叉，不要使用 T型锁叉。

**例外示例**：
```
原始名称：
单头锁叉 - T型 - 上头
单头锁叉 - T型 - 下头

输入条件：
mb = "T型铝材边"
mshd = "10"
spec = "970*2040/10/内开外包"

最终名称：
单头锁叉 - 上头
单头锁叉 - 下头
```

## 锁具类型识别

### P66 锁叉

**触发条件**：`sj`（锁具）字段 = `"SD-9030（6607大锁）"`

**效果**：在锁叉名称中添加 "P66" 后缀

**示例**：
```
原始名称：单头锁叉
检测到 sj = "SD-9030（6607大锁）"
最终名称：单头锁叉 P66
```

### 双头锁叉（直杆/弯杆）

**触发条件**：`fssj`（副锁锁具）字段 = `"F02-A副锁"`

**效果**：
- 上头标注为 **直杆**
- 下头标注为 **弯杆**

**示例**：
```
原始名称：双头锁叉
检测到 fssj = "F02-A副锁"

生成两条明细：
1. 双头锁叉 - 上头（直杆）
2. 双头锁叉 - 下头（弯杆）
```

## 常见问题

### Q1: 为什么带吊脚的下头基础是 313 而不是 301？
**A**: 带吊脚的门需要更长的锁叉，因此下头基础增加 12mm（301 + 12 = 313）。

### Q2: 高度调整为什么要除以 2？
**A**: 门高的变化需要平均分配到上头和下头，因此调整值为总变化的一半。

### Q3: 如果没有检测到吊脚，系统会怎么处理？
**A**: 系统会使用标准尺寸（上下头都是 570*301），不进行吊脚调整。

### Q4: T型和P66可以同时出现吗？
**A**: 可以。如果同时满足条件，名称会是 "单头锁叉 T型 P66"。

### Q5: `spec` 里的 `960*2400` 哪个是门高？
**A**: `960` 是宽度，`2400` 是高度。锁叉尺寸计算只使用高度。

### Q6: 5cm / 7cm 为什么在 2200 以上切换基础尺寸？
**A**: 2200 以上属于高门场景，业务上不再沿用 `570*301 / 570*313`，而是改用 `570*376 / 570*376` 或 `570*376 / 570*388`。

### Q7: 9cm 为什么单独用 2210 作为阈值？
**A**: 9cm 高门与 5cm / 7cm 不是同一套规则，当前业务要求 9cm 在 `>= 2210` 时才切换到 `524*422 / 524*272`。
