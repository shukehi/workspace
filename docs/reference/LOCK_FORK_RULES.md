## 概述

系统会自动从订单中提取锁叉信息（字段：`sc`），并根据以下规则生成采购明细：

- **锁叉分类**：单头锁叉、双头锁叉
- **子类**：T型、P66、直杆/弯杆、中控、螺纹等
- **一个订单会生成上头和下头两条采购明细**

---

## 基础尺寸规则

### 7cm 门厚标准尺寸

| 类型 | 上头基础 | 下头基础 |
|------|---------|---------|
| 标准（无吊脚） | 570 + 301 = 871 | 570 + 301 = 871 |
| 带吊脚 | 570 + 301 = 871 | 570 + 313 = 883 |

> **注意**：带吊脚的门，下头基础尺寸使用 **313** 而非 301（增加 12mm）

## 高度调整计算

### 基准高度：2050mm

当门高不等于 2050mm 时，需要进行高度调整：

**公式**：
```
高度调整值 = (实际门高 - 2050) / 2
```

**示例 1：2150mm 门高**
```
高度调整 = (2150 - 2050) / 2 = 50mm

上头 = 570*301 + 50 = 921
下头 = 570*301 + 50 = 921
```

**示例 2：1950mm 门高**
```
高度调整 = (1950 - 2050) / 2 = -50mm

上头 = 570*301 - 50 = 821
下头 = 570*301 - 50 = 821
```

## 吊脚检测与调整

### 检测规则

系统从 `xsbz`（销售备注）字段检测吊脚关键字：
- **关键字**：`吊脚`、`diaojiao`
- **提取数值**：如 "吊脚5mm" → 5

### 标准吊脚：35mm

**调整公式**：
```
吊脚调整值 = 35 - 实际吊脚值
```

**示例：吊脚 5mm**
```
吊脚调整 = 35 - 5 = 30mm

上头 = 570*301 = 871（无调整）
下头 = 570*313 + 30 = 913
```

> **重要**：吊脚调整**仅应用于下头**，上头保持标准尺寸

### 完整示例：2150mm 门高 + 吊脚 5mm

```
高度调整 = (2150 - 2050) / 2 = 50mm
吊脚调整 = 35 - 5 = 30mm

上头 = 570*301 + 50 = 921
下头 = 570*313 + 50 + 30 = 963
```

## 边型分类

### T型边检测

**触发条件**：`mb`（门边）字段包含 `"T型"`

**效果**：在锁叉名称中添加 "T型" 后缀

**示例**：
```
原始名称：单头锁叉
检测到 mb = "T型现代边"
最终名称：单头锁叉 T型
```

## 锁具类型识别

### P66 锁叉

**触发条件**：`sj`（锁具）字段 = `"SD-9030（6607大锁）"`

**效果**：在锁叉名称中添加 "P66" 后缀

**示例**：
```
原始名称：单头锁叉
检测到 sj = "SD-9030（6607大锁）"
最终名称：单头锁叉 P66
```

### 双头锁叉（直杆/弯杆）

**触发条件**：`fssj`（副锁锁具）字段 = `"F02-A副锁"`

**效果**：
- 上头标注为 **直杆**
- 下头标注为 **弯杆**

**示例**：
```
原始名称：双头锁叉
检测到 fssj = "F02-A副锁"

生成两条明细：
1. 双头锁叉 - 上头（直杆）
2. 双头锁叉 - 下头（弯杆）
```

## 配置文件说明

### 文件位置
`/data/config/lock-fork-mapping.json`

### 配置结构

```json
{
  "baseDimensions": {
    "7": {
      "standard": {
        "upper": { "base1": 570, "base2": 301 },
        "lower": { "base1": 570, "base2": 301 }
      },
      "withHangingFeet": {
        "upper": { "base1": 570, "base2": 301 },
        "lower": { "base1": 570, "base2": 313 }
      }
    }
  },
  "lockTypes": {
    "SD-9030（6607大锁）": {
      "category": "P66",
      "nameModifier": "P66"
    },
    "F02-A副锁": {
      "category": "dual-head",
      "upper": "直杆",
      "lower": "弯杆"
    }
  },
  "edgeTypes": {
    "T型": {
      "nameModifier": "T型"
    }
  },
  "hangingFeet": {
    "standard": 35,
    "keywords": ["吊脚", "diaojiao"]
  },
  "heightReference": 2050
}
```

### 如何添加新规则

#### 1. 添加新的锁具类型

```json
"lockTypes": {
  "新锁具名称": {
    "category": "custom",
    "nameModifier": "自定义标识"
  }
}
```

#### 2. 添加新的边型

```json
"edgeTypes": {
  "新边型": {
    "nameModifier": "新边型标识"
  }
}
```

#### 3. 添加其他门厚尺寸

```json
"baseDimensions": {
  "9": {
    "standard": {
      "upper": { "base1": 600, "base2": 320 },
      "lower": { "base1": 600, "base2": 320 }
    },
    "withHangingFeet": {
      "upper": { "base1": 600, "base2": 320 },
      "lower": { "base1": 600, "base2": 332 }
    }
  }
}
```

## 常见问题

### Q1: 为什么带吊脚的下头基础是 313 而不是 301？
**A**: 带吊脚的门需要更长的锁叉，因此下头基础增加 12mm（301 + 12 = 313）。

### Q2: 高度调整为什么要除以 2？
**A**: 门高的变化需要平均分配到上头和下头，因此调整值为总变化的一半。

### Q3: 如果没有检测到吊脚，系统会怎么处理？
**A**: 系统会使用标准尺寸（上下头都是 570*301），不进行吊脚调整。

### Q4: T型和P66可以同时出现吗？
**A**: 可以。如果同时满足条件，名称会是 "单头锁叉 T型 P66"。
