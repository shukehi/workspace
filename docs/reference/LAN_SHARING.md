# 局域网共享说明

本文说明如何将当前项目在同一个 Wi-Fi / 局域网内共享给其他同事访问，以及开发模式和稳定演示模式分别应该怎么启动。

## 适用前提

- 你和同事在同一个局域网
- 本机已安装依赖并可正常启动项目
- 操作系统防火墙允许 Node.js 接收局域网传入连接
- 公司网络没有开启终端隔离 / AP 隔离

## 方式一：开发模式共享

适合场景：

- 你一边开发，一边让同事同步查看当前页面
- 需要保留 Vite 热更新能力

启动命令：

```bash
npm run server:lan
npm run dev:lan
```

访问地址：

- 前端：`http://<你的局域网IP>:5173`
- 后端：`http://<你的局域网IP>:3000`

例如本机 IP 为 `172.16.0.10` 时：

- `http://172.16.0.10:5173`
- `http://172.16.0.10:3000`

行为说明：

- `npm run dev:lan` 仍然是 Vite 开发模式，只是将监听地址开放到局域网
- 同事访问前端时，`/api/*` 和 `/data/*` 仍由 Vite 代理到你本机的 `3000` 端口
- 你改动代码时，本机和同事页面都会看到最新结果

限制与风险：

- 同事会看到你当前正在开发中的状态，不保证稳定
- 热更新可能导致同事页面自动刷新
- 大家共用的是你本机上的后端和 SQLite 数据
- 你关闭本机服务后，同事访问会立即中断

## 方式二：构建后共享

适合场景：

- 你要给同事稳定演示
- 希望避免开发过程中的热更新影响演示

启动命令：

```bash
npm run share:prod
```

访问地址：

- 前端与后端统一由 Express 提供：`http://<你的局域网IP>:3000`

行为说明：

- 该模式服务的是构建产物 `dist`
- 同事看到的是一个相对稳定的版本，不会跟着你的编辑即时变化
- 如果你改了前端代码，需要重新执行 `npm run build`
- 如果你改了后端代码，需要重新启动 `npm run server:prod`

更新规则：

- 只改前端：重新执行 `npm run build`，然后让同事刷新页面
- 改了后端：停止当前 `server:prod` 进程后重新启动
- 前后端都改了：重新执行 `npm run share:prod` 最直接

## 推荐选择

- 日常联调、内部协作排查问题：使用“开发模式共享”
- 稳定演示、给业务或同事试用：使用“构建后共享”

## 常见问题

### 1. 本机共享给别人后，自己还能继续开发吗？

可以。

`npm run dev:lan` 本质上仍然是开发模式，只是监听 `0.0.0.0`，而不是默认的 `localhost`。你仍然可以正常获得热更新、调试日志和本地开发体验。

### 2. 为什么前端能访问到本机后端？

因为前端开发服务器会把 `/api/*` 和 `/data/*` 代理到本机 `localhost:3000`。同事访问的是你的 Vite 地址，但真正的 API 请求仍由你的机器转发给本机后端。

### 3. 同事打不开页面，优先检查什么？

按这个顺序排查：

1. 确认双方处于同一局域网
2. 确认本机 IP 没变
3. 确认 `npm run server:lan` 和 `npm run dev:lan` 都还在运行
4. 确认系统防火墙未拦截 Node.js
5. 确认公司 Wi-Fi 没有限制终端互访

### 4. 打印 / PDF 在局域网下是否可用？

开发环境下通常可用。

当前项目在非生产环境会优先根据请求头中的 `Origin/Referer` 推断渲染基地址，因此同事从局域网地址访问时，打印相关逻辑通常会跟随该地址工作。

### 5. 构建后共享时，代码更新后是否必须重新执行命令？

是，但要区分前端和后端：

- 只改前端代码：必须重新 `npm run build`
- 改了后端代码：必须重启 `npm run server:prod`
- 想用一个统一命令处理：直接重新执行 `npm run share:prod`
